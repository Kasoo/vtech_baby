# 05 — The current setup, and what it costs

How the integration reaches the camera today, layer by layer, and which parts of that the new design
keeps, replaces or drops. The point of this document is to separate **what the wire needs** from
**what the SDK's shape imposed**.

## The stack today

```
Home Assistant process
  manager.py ── worker_client.py ──(pickles over a socketpair)──┐
                                                                 │
Worker process (python -I)                                       ▼
  worker.py ── Session (session.py) ── reader thread, keepalive thread
            ── LiveStream (media.py) ── media thread: 5 ms poll, Python decrypt, PyAV mux
            ── TalkBack (talkback.py) ── talk thread: Python encrypt, time.sleep pacing
            ── HTTP server thread(s): MPEG-TS on a loopback socket HA passed in
  sdk.py (ctypes)
    └── libAVAPIs.so      rx thread + tx thread per AV channel, polled waits
        └── libIOTCAPIs.so   per-channel linked-list queues, table lock, DTLS via OpenSSL BIO
            └── libTUTKGlobalAPIs.so   connection-manager thread, task-manager thread,
                                       licence RSA/JSON, egress filter, OpenSSL forwarders
                └── host libssl.so.3 / libcrypto.so.3
```

`tutk-host/` is about 4,100 lines of C across 42 files, plus 1,700 lines of C and Python tests. It
implements a surface of 250-odd exported symbols, most of them abort stubs generated by
`tools/gen_stubs.py`.

## What the C mirror carries that the wire does not need

| SDK structure (where in `tutk-host`) | Why it exists | Fate in `vtech-link` |
|---|---|---|
| Exported `IOTC_*`/`av*` API, session ids, AV indexes, the slot table with refcounts (`av/init.c:24–110`) | Drop-in ABI for the vendor app and our ctypes layer | **Dropped.** A link is an object; handles are Rust values. |
| Licence decode: base64, raw RSA-1024 public decrypt, XOR, SHA-256 check, JSON parse (`global/licence.c`, `global/crypto.c`, `global/json.c`, 730 lines) | `TUTK_SDK_Set_License_Key` | **Dropped.** Its only wire effect is the scramble key's mask, and our licence carries no `keyMask`, so the key is the bare constant (`tutk-kit/docs/iotc/15-wire-format.md`, "The scramble key"). A unit test pins this (`85-testing.md`). |
| Master-server names (`global/licence.c` `GetMasterDomainName`) | Cloud path | **Dropped.** |
| Connection manager: refcounted socket objects with 15-slot vtables, command queue, a poll thread, wake pipe (`global/connections.c`, 563 lines) | Global's generic socket layer | **Replaced** by one non-blocking UDP socket per link on its own event loop (`70-runtime.md`). |
| Task manager: a thread running interval tasks under a global lock (`global/tasks.c`) | LAN-search and keepalive tasks | **Replaced** by deadlines in the link's state machines. |
| Platform wrappers, lists, TList/TutkList (`global/platform.c`, `global/lists.c`) | SDK portability layer | **Dropped.** |
| OpenSSL forwarders `tutk_third_*` and the generated stand-ins (`tools/gen_stubs.py`, `lib.mk`) | The SDK reaches OpenSSL through Global | **Dropped** along with OpenSSL itself (`30-dtls.md`). |
| A process-wide session table of 128 slots with one recursive lock taken by every call and every inbound datagram (`iotc/init.c`, `iotc_session_enter`) | `IOTC_*` takes integer session ids | **Replaced** by per-link state owned by one thread; no shared table. |
| One shared UDP socket for all sessions, demultiplexed by token (`iotc/discovery.c:14`, `iotc/inbound.c:35`) | SDK design | **Replaced** by a socket per link. The token check stays, as a filter. |
| Per-channel receive queues of malloc'd packets, drained by 10 ms polling reads (`iotc/data.c`) | `IOTC_Session_Read` | **Dropped.** Inbound data goes straight from the datagram to the channel's state machine. |
| DTLS through OpenSSL with a custom BIO that polls IOTC every 20 ms (`iotc/dtls.c:56`), a PSK callback registry, and `IOTC_sCHL_*` wrappers | The SDK's secure channel | **Replaced** by a sans-IO DTLS client for one suite (`30-dtls.md`). |
| `IOTC_Session_Check`/`_Ex` info blocks, close callbacks with a magic number (`iotc/session.c`) | API shape | **Replaced** by `Link.info()` and a lost event. |
| NAT tracking, try-port, address codecs, nonce update (`iotc/nat.c`, `tryport.c`, `addresses.c`) | Called on init or on P2P paths | **Dropped.** |
| Two threads per AV channel (`av_read_task`, `av_tx_task`), with waits that poll every 5 ms (`av/session.c:119`, `av_wait`) | SDK structure; the polling was inherited from the drop-in build's companion mutexes | **Replaced** by the link thread's event loop and condition variables. |
| The AV login deadline derived from the peer protocol version (`av/session.c:229`) | Stock behaviour | **Simplified** to the caller's AV timeout (R3). |
| `avServStart3` + auth callback + `avServStop`/`avServExit`/`avServResetBuffer` (`av/talkback.c`) | API shape | **Replaced** by a `TalkBack` object (`50-talkback.md`). |
| Parity, receive counters, NAK, gap skip (`av/fec.c`, `av/media_recv.c`) | Our own additions; correct and live-proven | **Kept** in behaviour, ported (`45-media-receive.md`). |

The wire behaviour in `tutk-host` (`iotc/wire.c`, `handshake.c`, `inbound.c`, `data.c`;
`av/session.c` login; `av/transport.c`; `av/ioctrl.c`; `av/media_recv.c`; `av/media_send.c`;
`av/talkback.c`; `av/fec.c`) is the reference for every byte the new code sends and accepts.

## What the Python side does to fit the SDK

| Code | Why | Fate |
|---|---|---|
| `sdk.py`: ctypes bindings, struct packing (`AvIn`, the 160-byte connect input), `preflight` page-size and ELF checks | Calling C through ctypes | **Replaced** by the PyO3 module (`75-python-api.md`). |
| `native.py` + `tooling/` + `config_flow.py` upload step: extract, patch and fingerprint the vendor SDK | The patched-vendor fallback | **Dropped** (already planned once the `tutk-host` soak ends). |
| `session.py` reader thread looping on `avRecvIOCtrl(1000 ms)`; waiter dict; `_send_lock`; `SEND_BUSY` retry loop | SDK's single-reader and single-sender rules | **Moved** into the library (R11–R14). Python keeps a thin `Session` with the same public methods. |
| `media.py` 5 ms polling of `avRecvFrameData2`/`avRecvAudioData`, 2 MiB ctypes buffer copies, per-frame Python decrypt | SDK's non-blocking frame calls | **Replaced** by a blocking `next()` returning decrypted frames (R18, R22). |
| `crypto.py` X25519/HMAC/ChaCha20 with `cryptography`, a byte-by-byte Python XOR per frame (`_xor`) | Application crypto above the SDK | **Moved** into Rust (R17, R18, R26). |
| `talkback.py` `time.sleep` pacing, `serv_reset` on `-20006` | SDK talk-back API | **Simplified**: pacing and framing move into Rust (R26, R28). |
| `worker.py`, `worker_client.py`, `ipc.py`, `_worker_main.py` (~900 lines): process isolation, pickled RPC, crash Repairs issue | A native crash in the C SDK kills its process | **Kept during migration, then retired** (`90-migration.md`). The MPEG-TS HTTP server moves into HA's process. |

## Costs we pay today

- **Polling latency and CPU.** A waiting caller is woken every 5–20 ms: `av_wait` 5 ms, IOTC reads
  10 ms, the DTLS BIO 20 ms, media reads 5 ms. Inbound media passes through four hand-offs before
  Python sees it: datagram → IOTC queue → DTLS read → AV assembly → ctypes copy.
- **Thread count.** Each link costs two AV threads, plus a talk-back pair while talking, plus the
  process-wide connection-manager and task-manager threads, plus three Python threads (reader,
  keepalive, media).
- **A global lock.** Every IOTC call and every inbound datagram, for every camera, takes
  `iotc.table_lock`.
- **Error codes as control flow.** `-20012`/`-20011` mean "nothing yet", `-20021`/`-20029` mean
  "busy, retry", `-20000` on a receive means "gone". These are hard to read and easy to get wrong.
- **C memory safety.** `tutk-host` has had no crash in the field. The fuzzing and review a C protocol
  parser needs would cost more than writing it in safe Rust. The worker process only limits the damage
  of a crash; it doesn't stop one happening.
- **An OpenSSL dependency.** Our builds link against stand-ins and borrow the host's
  `libssl.so.3` at run time. That forces the import allow-list work in `release.sh` and leaves a
  failure mode if the host's OpenSSL changes.
- **A wrong-password failure that looks like an unreachable camera.** A failed DTLS handshake becomes
  `AV_ER_TIMEOUT` (`av/session.c:217` `handshake_error`), which `errors.py` maps to `Unreachable`.
  The new DTLS client sees the camera's alert and reports `AuthFailed` (`30-dtls.md`).

## What already works well and is kept

- The **protocol facts** in the kits and their encoding in `tutk-host`.
- The **loss handling**: NAK timing, the gap skip, the frame give-up, parity recovery, and the
  counters. All of it is live-tested (`tutk-host/NOTES.md`).
- The **integration above the session**: `manager.py`, the entities, `ops.py`, `avmux.py`, `audio.py`,
  the reconnect and stale-credentials logic, and the 234 offline tests.
- The **live probe harness** (`tests/live/`, the camera repo's `shim/tests/live_run.sh`).
